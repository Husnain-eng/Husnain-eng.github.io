01 / RESEARCH

Two research directions.
One systems mindset.

The portfolio is deliberately organized around the two areas where my existing work forms the clearest technical narrative. The first begins with sensing and autonomy; the second begins with models, control, and physical actuation.

Research principle. A robot is only as good as the weakest interface between its layers. Sensor placement affects perception. Estimation affects planning. Planning affects control. Controller timing affects physical behavior. Mechanical constraints feed back into every one of those decisions.

My goal is to work on the parts of robotics where these interfaces become research problems: robustness in dynamic environments, efficient perception on constrained compute, real-time feedback, kinematic control, and hardware-software co-design.

01

AMR — ROS2 Navigation & Sensor Integration

An autonomous mobile robot platform connecting mechanical structure, LiDAR/RGB-D perception, ROS2 navigation, SLAM, sensor fusion, and dynamic obstacle handling.
ROS2 · Nav2 · SLAM · LiDAR · RGB-D · sensor fusion · SolidWorks
+

Problem

The robot needed to navigate indoors while carrying its own sensing and compute stack. The challenge was not only choosing a navigation package, but placing sensors and mechanical structures so the perception system retained the field of view and geometry it needed.

Role & scope

Mechanical design and sensor integration in the Human Centered Robotics Lab, NCRA, UET Lahore, supervised by Dr. Ali Raza.

Technical approach

  • Designed chassis mounts, sensor brackets, and mast assemblies in SolidWorks, checking clearances, mass properties, center-of-gravity, and physical interfaces before fabrication.
  • Integrated LiDAR and RGB-D sensors while accounting for mounting geometry and usable sensing volume.
  • Supported the ROS2 navigation stack through SLAM, dynamic path planning, and multi-sensor integration, keeping the mechanical and software layers consistent.
  • Worked toward navigation behavior that could handle changing obstacles rather than assuming a static map.

Engineering lesson

Sensor integration is a mechanical problem as much as a software problem. A theoretically capable navigation stack can still fail when the physical mounting introduces occlusion, vibration, poor frame placement, or misleading geometry.

Result: working indoor mobile-robot navigation and dynamic-obstacle behavior, with the platform reused as the base for subsequent robotics work.
Research signal
Full-stack mobile robotics integration: sensing → estimation → planning → physical motion.

02

Real-Time Closed-Loop IK Control — 3-DOF Manipulator

A physical manipulator controlled through closed-form inverse kinematics, encoder feedback, and deterministic real-time trajectory execution.
NI myRIO · LabVIEW · inverse kinematics · encoder feedback · trajectory tracking
+

Problem

A 3-DOF manipulator needed continuous end-effector motion rather than point-to-point movement. The controller had to transform Cartesian trajectories into joint commands and maintain feedback during execution.

Role & scope

Full real-time control system design and implementation.

Technical approach

  • Formulated closed-form geometric inverse kinematics to map desired end-effector positions to joint angles.
  • Combined IK with encoder-feedback closed-loop control to correct trajectory error during motion.
  • Implemented real-time control logic in LabVIEW on NI myRIO with deterministic data flow.
  • Generated and tracked circular and triangular end-effector paths rather than testing only static poses.
  • Added an IR-based safety interlock that halts motion when an obstacle is detected.

Engineering lesson

Inverse kinematics is only the geometric layer. The physical result depends on feedback, execution timing, motor response, and how continuously the controller corrects the difference between the desired and measured state.

Result: continuous circular and triangular spatial trajectory tracking with a working obstacle-triggered safety interlock.
Research signal
Embodied control: mathematical model directly coupled to real-time physical actuation.
Control loop
Cartesian target → IK → joint command → encoder feedback → correction
Core fit
Control · kinematics · trajectory tracking · real-time systems
03

Embedded C Stability Control System

A self-designed embedded controller using a TIVA microcontroller, bare-metal firmware, PID control, PWM actuation, motor monitoring, and vision-based orientation feedback.
TIVA TM4C123GH6PM · Embedded C/C++ · PID · BLDC · OpenCV · PWM
+

Problem

A dual-axis aerial platform needed real-time stabilization while using a non-conventional sensing approach rather than relying on a standard IMU.

Role & scope

End-to-end hardware and firmware work: custom controller board, bare-metal software, motor actuation, sensing, and feedback control.

Technical approach

  • Designed a self-built TM4C123GH6PM-based PCB for the control system.
  • Wrote bare-metal C/C++ firmware with prioritized interrupt handling and timer-driven PWM generation.
  • Monitored RPM and current to connect commanded actuation with the actual motor state.
  • Implemented PID attitude control to drive two BLDC motors and counter disturbance-induced oscillation.
  • Closed the orientation loop with OpenCV-based visual estimation instead of a conventional IMU.

Engineering lesson

Control performance cannot be separated from embedded timing and measurement quality. Interrupt structure, PWM timing, sensing latency, and motor response all become part of the practical controller.

Result: the control response was validated on the physical rig, demonstrating end-to-end hardware-to-control integration.
Research signal
Low-level real-time control with custom electronics and a non-standard sensing pipeline.

04

Autonomous UV-C Disinfection Robot

A mobile robot combining autonomous coverage, mechanical deployment, static structural FEA, and optical analysis for operating-theatre disinfection.
SolidWorks · static FEA · MATLAB · DIALux Evo · COMSOL · autonomous coverage
+

Problem

Vertically mounted UV-C sources can leave shadowed regions. The system therefore needed to solve a coverage problem together with the mechanical and safety constraints of moving a multi-lamp array through an operating environment.

Role & scope

Full mechanical design and FEA validation with Dr. Ali Raza and Dr. Maria Akram; manuscript in preparation.

Technical approach

  • Designed a differential-drive chassis with a central mast and umbrella-style multi-angle UV-C mechanism supporting an 8-lamp array.
  • Evaluated the structure through static FEA across open and closed configurations, including stress, deflection, factor of safety, and mesh convergence.
  • Used mechanical analysis to inform material and section selection instead of relying only on visual CAD judgment.
  • Cross-validated optical behavior through MATLAB, DIALux Evo, and COMSOL to produce a three-dimensional irradiance/dose representation.
  • Connected the robot's navigation role to systematic coverage of the target space.

Engineering lesson

Robotic systems in physical environments are multi-domain problems. Mechanical geometry, structural integrity, coverage planning, perception, and safety cannot be optimized independently.

Result: tip deflection was held below 5 mm at full lamp load; the physical build was fabricated and checked against the CAD model.
Research signal
Embodied autonomy under mechanical, safety, and coverage constraints.
Validation
FEA · mesh convergence · optical simulation · physical fabrication
Core fit

Tiva TM4C123GH6PM Development Board

A manufacturing-oriented reconstruction of a Tiva development board covering schematic design, footprints, multilayer layout, rule verification, 3D fit, and fabrication release.
KiCad · IPC-2221 · IPC-7351 · DRC/ERC · Gerbers · BOM
+

Problem

The goal was to reproduce a usable embedded development platform from technical references and carry it far enough toward manufacturing that the design could be reviewed as a real board rather than a classroom schematic.

Technical approach

  • Reconstructed the MCU, regulated power supply, oscillator/clock network, USB interface, headers, protection, and support passives from datasheets and reference designs.
  • Created custom symbols and IPC-7351 footprints where required.
  • Applied IPC-2221 guidance to trace width, spacing, and current/voltage considerations.
  • Completed multilayer routing with explicit ground and power planes.
  • Ran full DRC/ERC checks and used the 3D board model to inspect mechanical fit.

Release

Prepared Gerber and drill files, assembly drawings, and a bill of materials for fabrication review.

Result: complete manufacturing-oriented PCB release package rather than a design that stopped at schematic capture.
Research signal

06

TinyML — Visual Wake Words

A resource-constrained embedded perception pipeline from image classification through INT8 quantization and on-device ESP32-CAM inference.
CNN · TensorFlow Lite · INT8 quantization · 96×96 input · ESP32-CAM
+

Problem

Person detection had to run on resource-constrained hardware without depending on cloud inference or a workstation in the loop.

Technical approach

  • Designed and trained a CNN for person detection on 96×96 imagery.
  • Converted the model to TensorFlow Lite and quantized the inference path to INT8.
  • Stress-tested low-light conditions, sensor noise, and lens blur before deployment.
  • Deployed inference directly on an ESP32-CAM for an end-to-end edge pipeline.

Engineering lesson

Embedded perception is not simply a smaller version of desktop perception. The model, input resolution, numerical precision, memory budget, sensing quality, and runtime all have to be designed together.

Result: an end-to-end TinyML pipeline from training and quantization to real-time on-device inference.
Research signal
Edge perception and the trade-off between model complexity, robustness, and embedded compute.
Deployment
ESP32-CAM · TensorFlow Lite · INT8
Core fit
Perception · embedded AI · resource-constrained robotics
